2026.10.28 파이썬 가상환경 구축과 pip install ▾
S

Situation · 상황

파이썬 프로젝트를 진행하려는데, 패키지를 전역(global)에 설치하면 다른 프로젝트와 버전이 충돌할 것 같아 걱정이었다.

T

Task · 과제

프로젝트별로 독립된 가상환경(venv)을 만들고, 그 안에서 pip install로 패키지를 설치하는 흐름을 익히고 싶었다.

A

Action · 행동

  • python -m venv venv → 가상환경 폴더 생성
  • source venv/bin/activate (macOS/Linux) 또는 venv\Scripts\activate (Windows) → 가상환경 활성화
  • pip install <패키지명> → 가상환경 안에 패키지 설치
  • pip list → 설치된 패키지 확인
  • deactivate → 가상환경 종료
R

Result · 결과

가상환경을 활성화한 상태에서만 pip install이 해당 환경에 적용된다는 것을 알게 되었다. 프롬프트 앞에 (venv)가 붙으면 활성화된 상태라는 표시라는 점도 확인했다. 프로젝트마다 환경을 분리하면 버전 충돌을 피할 수 있다는 걸 이해했다.

2026.10.29 Flask와 schedule이 뭔지 찾아보다 ▾

T

Task · 과제

궁금해서 직접 찾아보기로 했다. 각각 어떤 역할을 하고, 대충 어떻게 쓰는 건지만 알아보는 게 목표였다.

A

Action · 행동

  • Flask : 파이썬으로 웹페이지를 만들 때 쓰는 도구. 주소(/)랑 그 주소에서 보여줄 코드를 연결해주는 방식이고, HTML 파일도 같이 불러올 수 있다는 걸 알게 됐다.
  • schedule : 정해진 시간마다 내 코드를 자동으로 실행시켜 주는 도구. schedule.every(10).seconds.do(함수) 처럼 "10초마다 이 함수 실행" 식으로 읽히듯이 쓸 수 있다는 게 신기했다.
R

Result · 결과

Flask는 웹사이트를 만들어주는 도구, schedule은 시간 맞춰 코드를 실행해주는 도구라는 차이를 알게 됐다. 아직 직접 써보진 않았지만, 과제에서 왜 이 둘을 설치하라고 했는지 감이 잡혔다.

2026.10.30 Gemini API 키 발급과 파이썬 파일 입출력 ▾
S

Situation · 상황

Gemini API 키를 발급받아 .env에 넣어보고, 파이썬 파일 입출력을 배웠다

T

Task · 과제

과제에서 시킨 대로 API 키를 .env에 보관하고, 그 키로 모델 목록을 확인해보는 것. 그리고 파이썬에서 파일을 읽고 쓰는 것까지 해보는 게 목표였다.

A

Action · 행동

  • API 키 발급 → .env에 저장 : 키를 코드에 그대로 쓰지 않고 .env 파일에 따로 넣어 관리한다는 걸 알게 됐다.
  • curl로 요청 → grep으로 확인 : 터미널에서 curl로 Gemini API에 요청을 보내고, 응답 중 gemini-3.5 모델이 목록에 있는지 grep으로 걸러서 확인했다.
  • 파이썬 파일 입출력 : with open(...) 으로 파일을 열어 읽고 쓰는 방식을 해봤다. with를 쓰면 파일을 자동으로 닫아준다는 걸 알게 됐다.
R

Result · 결과

  • API 키는 코드에 직접 쓰지 않고 .env 같은 파일에 따로 보관한다는 걸 이해했다.
  • curl로 API를 직접 찔러보고 grep으로 결과를 걸러 확인하는 흐름을 익혔다.
  • 파이썬 파일 입출력은 with open으로 여는 게 기본이라는 것, 그리고 with를 쓰면 close를 따로 안 해도 된다는 걸 알게 됐다.
2026.11.02 기존 폴더를 GitHub 저장소와 연결하기 ▾
S

Situation · 상황

지금까지는 PC 폴더와 GitHub 저장소가 따로 있어서 파일을 웹 화면에서 하나씩 올렸다. 하지만 security-agent-toolkit 폴더는 이미 GitHub에 올려둔 상태라, 폴더를 내려받거나 옮기지 않고 그 자리에서 GitHub 저장소와 연결하는 과제가 나왔다.

T

Task · 과제

security-agent-toolkit 폴더를 그대로 둔 채 GitHub 원격 저장소와 연결하고, .env·.venv 같은 민감/불필요 파일은 올라가지 않게 .gitignore로 막은 뒤, git status로 정상 연결 상태를 확인하는 것이 목표였다.

A

Action · 행동

  • VS Code 통합 터미널에서 pwd로 경로가 .../security-agent-toolkit으로 끝나는지 확인 (agent_core면 cd ..)
  • GitHub에서 Code → HTTPS 주소 복사
  • git init -b main → 이 폴더를 git 폴더로 만들고 첫 브랜치 이름을 main으로
  • git remote add origin <내 주소> → GitHub 저장소를 origin으로 등록
  • git fetch origin → GitHub에 있던 기록을 받아옴
  • git reset origin/main → 내 폴더의 기록 위치를 GitHub 기록에 맞춤 (--hard 없이, 내 파일은 그대로)
  • git branch -u origin/main → 다음부터 git push만 써도 되게 짝(업스트림)을 정함
  • git status → On branch main 확인
  • .gitignore에 .env, .venv 두 줄 추가 후 다시 git status로 목록에 없는지 확인
R

Result · 결과

  • git status에 On branch main 과 Your branch is up to date with 'origin/main'이 뜨는 걸 보고, 폴더가 GitHub 저장소와 제대로 연결됐다는 걸 확인했다.
  • git init은 로컬 폴더를 git이 기록하는 폴더로 만드는 것, git remote add는 그 폴더와 GitHub 저장소를 짝지어 주는 것이라는 차이를 이해했다.
  • git reset origin/main은 내 파일은 건드리지 않고 기록 위치만 GitHub에 맞추는 명령이고, --hard를 붙이면 파일이 덮어써진다는 걸 알게 됐다.
  • .gitignore에 .env·.venv를 넣으면 git status 목록에서 아예 사라진다는 것도 확인했다. 민감한 파일을 실수로 올리는 걸 막는 게 이 설정의 목적이라는 걸 이해했다.
  • 추가로 ls -a로 숨김 폴더 .git이 보이는지, git log --oneline으로 10/26부터 웹에서 올린 기록이 한 줄씩 보이는지 확인했다.
2026.11.03 딕셔너리 접근법과 JSON 사용법 ▾
S

Situation · 상황

과제에서 agent_core에 assignment_08_f1.py와 assignment_08_f2.py를 직접 작성하라고 했다. 리스트는 번호로 꺼내는데, 로그 한 줄처럼 여러 정보가 묶인 데이터는 번호만으로는 "3번이 뭐였는지" 기억하기 어려웠다.

T

Task · 과제

딕셔너리로 이름(키)으로 값을 꺼내는 법과, 그 딕셔너리를 JSON으로 저장·복원하는 법을 익히고, 필수 F1·F2와 선택 문제 R1~R7까지 풀어보는 것이 목표였다.

A

Action · 행동

  • 딕셔너리 기본 : user["name"]처럼 키로 값 꺼내기, user["level"] = "admin"처럼 있는 키는 바꾸고 없는 키는 새로 생기는 것 확인
  • .get() : 없는 키를 대괄호로 꺼내면 KeyError로 멈추지만, log.get("ip")는 None, log.get("ip", "-")는 기본값을 돌려줌
  • 중첩 : logs[0]["user"](리스트 안 딕셔너리), report["admin"]["fail"](딕셔너리 안 딕셔너리), alerts[0]["tags"][1](값 자리에 리스트)
  • JSON : json.dumps()/json.loads()는 글자로, json.dump()/json.load()는 파일로, ensure_ascii=False·indent=2 설정
  • 필수 F1·F2 및 선택 R1~R7까지 직접 작성·실행 (R7에서 중첩 꺼내기까지)
R

Result · 결과

  • 리스트는 같은 것이 여러 개일 때, 딕셔너리는 하나에 대한 여러 정보를 담을 때 쓴다는 차이를 이해했다.
  • []는 반드시 있어야 하는 값에, .get()은 없을 수도 있는 값에 쓴다는 걸 알게 됐다. 항상 .get()을 쓰면 없는 게 문제인 값까지 조용히 넘어가서 오히려 버그를 찾기 어려워진다는 점이 인상적이었다.
  • 중첩은 바깥은 번호, 안쪽은 이름(또는 그 반대)을 번갈아 쓰면 된다는 규칙을 잡았다.
  • dumps는 s가 붙으면 글자, dump는 파일이라는 차이, 그리고 ensure_ascii=False를 안 넣으면 한글이 \uc57c처럼 깨진다는 걸 직접 확인했다.
  • R7까지만 풀었고, R8 이후(JSON 한글·파일 저장 등)는 다음에 이어서 하기로 했다.
